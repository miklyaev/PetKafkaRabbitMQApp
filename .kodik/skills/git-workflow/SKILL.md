## Overview

Навык описывает стандартный workflow работы с git в этом проекте: создание коммитов, пуш в удалённый репозиторий, работа с ветками и аккуратная отмена изменений.

## Guidelines

- Рабочая ветка по умолчанию — `main`, удалённый репозиторий — `origin` (GitHub).
- Перед коммитом проверяй состояние: `git status`.
- Сообщения коммитов — на английском, в формате `<тип>: <краткое описание>` (например `fix:`, `feat:`, `test:`, `docs:`).
- **Кодировка**: в PowerShell кириллица в сообщениях коммитов отображается кракозябрами. Используй только латиницу в сообщениях коммитов.
- Не коммить служебные файлы (`.env`, секреты, `node_modules`).
- Не используй деструктивные команды (`git reset --hard`, `git checkout --`) без явного запроса пользователя.
- После коммита делай пуш: `git push origin <branch>`.

## Workflow

1. Проверить состояние: `git status`
2. Добавить изменения: `git add <file>` или `git add -A`
3. Создать коммит: `git commit -m "<type>: <описание>"`
4. Запушить: `git push origin <branch>`
